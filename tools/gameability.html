gameability v0.2

Python package. Runs on a laptop, no model or API key.

Finds problems in a code benchmark that accept broken solutions. It breaks each problem's reference solution in one small place, confirms the result is really wrong, then checks whether the problem's own tests notice.

Quick Install
$ pip install "gameability[hf]" && gameability check mbpp
Methodology

How it works

The tool evaluates benchmark test sensitivity through five sequential steps:

  1. Load problem & reference solution: Retrieve the task prompt, canonical reference implementation, and official test suite.
  2. Apply single small edit: Break the reference solution in one small place (e.g. operator mutation, off-by-one boundary, branch perturbation).
  3. Confirm wrongness: Confirm that the perturbed result is genuinely incorrect against semantic specification before proceeding.
  4. Execute problem's own tests: Run the problem's official test harness against the broken code.
  5. Check for detection: Record whether the test suite notices. If the broken solution passes every visible test, flag the problem as gameable.

Boundary Conditions

Limits

Explicit Measurement Boundaries
  • The attacker is a single small edit (a floor, not a ceiling).
  • It audits tests, not models.
  • It does not predict where a specific model will cheat.
